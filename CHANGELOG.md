# Changelog

Все значимые изменения в проекте будут задокументированы в этом файле.

## [3.10.9-beta] - 2026-04-23

### 🎉 Стабильная бета-версия с новой архитектурой

**Полный переход на CIDR-списки, быстрое восстановление, проверка handshake.**

### Добавлено
- **13 источников готовых CIDR-списков** (подсетей) от проверенных проектов.
- **Быстрое восстановление ipset** из локального CIDR-файла (5–10 секунд после перезагрузки).
- **Проверка готовности VPN** через `awg show handshake` (надёжнее, чем `curl`).
- **Ожидание WAN** через `wget --spider` (гарантирует доступность HTTP/DNS).
- Сохранение и загрузка выученных IP (`learned_ips.cache`).
- Watchdog с автообучением (анализ `dmesg`).

### Изменено
- **Удалена** зависимость от доменных списков и резолва через `nslookup`.
- **Упрощена** логика обновления: больше нет кэша доменов и хешей источников.
- **Увеличены таймауты** ожидания сети до 120 секунд для медленных handshake.
- **Оптимизирована** автозагрузка: задержки 60 и 90 секунд.

### Исправлено
- Ошибка `Set bypass_nets doesn't exist` при добавлении правил iptables.
- Проблема с `grep -oP` в BusyBox (заменено на POSIX-совместимые выражения).
- Зависание скрипта при отсутствии интернета на старте.
- Неполное сохранение дампа `ipset save` (теперь сохраняется исходный CIDR-файл).

### Производительность
- Охват: **66 000+ подсетей** (миллионы IP).
- Восстановление после перезагрузки: **5–10 секунд**.
- Полное обновление: **2–3 минуты** (раз в 6 часов).


## [3.8.2] - 2026-04-22

### Добавлено
- **Блокировка повторного запуска** основного скрипта через lock‑файл (`/tmp/ipset_update.lock`).
- В watchdog добавлена проверка lock‑файла перед запуском `ipset_update.sh`.

### Изменено
- **Оптимизировано ожидание туннеля:** однократная быстрая проверка `curl` (5 секунд) вместо цикличного ожидания.
- **Исправлена функция `cache_is_fresh()`:** теперь использует `date -r` с fallback'ом на `ls --time-style=+%s`, что гарантирует корректную проверку свежести кэша в BusyBox.
- Увеличена задержка в автозагрузке до 60 секунд с повторной попыткой через 30 секунд.

### Исправлено
- Устранена проблема множественных параллельных запусков скрипта после перезагрузки.
- Устранено зависание скрипта на этапе ожидания готовности туннеля.
- Исправлена ошибка, из-за которой скрипт всегда выполнял полный резолв вместо восстановления из кэша.

## [3.8.1] - 2026-04-21

### Добавлено
- **Автоматическое определение параметров VPN-интерфейса.** Скрипт `ipset_update.sh` теперь сам определяет номер таблицы маршрутизации (`TABLE_ID`) и метку (`MARK_VALUE`) на основе текущей конфигурации. Это обеспечивает совместимость с различными сборками Padavan.

## [3.8] - 2026-04-21

### Добавлено
- **Автообучение watchdog:** каждые 60 секунд анализируется `dmesg` на предмет неудачных SYN-пакетов к порту 443. IP-адреса назначения автоматически добавляются в `bypass_domains`. Позволяет открывать сайты, блокируемые провайдером путём сброса TCP-соединения (TCP Reset).
- Исправлено регулярное выражение для поиска записей в `dmesg`: теперь поддерживается любой порядок полей `DPT=443` и `SYN`.

### Изменено
- Увеличен интервал анализа автообучения до 60 секунд (переменная `ANALYZE_INTERVAL`).
- Обновлены комментарии и номер версии во всех скриптах.

## [3.7-beta] - 2026-04-19

### Добавлено
- **Поддержка IPv6:** создаётся отдельный ipset `bypass_domains6`, настраиваются `ip6tables` и policy routing для IPv6. Трафик IPv6 к сайтам из списков направляется через туннель WARP.
- **Правила CONNMARK:** добавлены правила `iptables` для сохранения метки `0xca6c` в conntrack и её восстановления для ответных пакетов. Улучшает стабильность соединений для сервисов, чувствительных к потере маршрута.
- **Автовосстановление ipset в watchdog:** если количество записей в `bypass_domains` падает ниже 100, watchdog автоматически запускает `ipset_update.sh`.
- Расширенные проверки в watchdog: добавлен контроль правил CONNMARK, ip6tables и IPv6 policy routing.

## [3.6] - 2026-04-17

### Добавлено
- Первая стабильная версия.
- Основной скрипт `ipset_update.sh` с поддержкой динамических списков `itdoginfo` и статических доменов.
- Настройка `dnsmasq` для мгновенного добавления IP при DNS-запросах.
- Policy routing (таблица 51, метка `0xca6c`) для направления трафика через `wg0`.
- Watchdog для восстановления правил `ip rule`, таблицы 51, `rp_filter` и `iptables MARK`.
- Ежедневный cron на 04:00.
- Автозагрузка с задержками.

## [3.5] и ранее
- Экспериментальные версии, не предназначенные для широкого использования.
